# OpenAC（0.3 后续开发分支）

免费、MIT 开源的非官方 Windows 桌面应用，按 Armoury Crate 的导航、设备入口和页签重新实现。此分支正在开发，尚不能完整替代 Armoury Crate，也未完成所有设备控制和原版视觉复刻。已发布的 `v0.3.0-preview` 不包含此分支后续改动。

本轮按用户要求删除“内容”“功能库”“用户中心”，将“设置”改为 OpenAC 的“更新库”。“检查更新”直接查询本项目 GitHub Releases；原厂 BIOS/驱动目录位于“工具 → 驱动程序更新”。源码保存后的桌面实时预览见 [LivePreview.md](LivePreview.md)。官方设备范围和实际控制能力分开记录，见 [DeviceSupportCatalog.md](DeviceSupportCatalog.md)；逐页排版差异见 [OriginalUiInventory.md](OriginalUiInventory.md)。

## 运行

可在 [Releases](https://github.com/Lucas0623z/OpenAC/releases) 选择安装包或便携 ZIP。安装包仅写入当前用户的 Programs\OpenAC，需手动勾选许可后安装，不自动启动；卸载保留配置，已有版本需先卸载。选择便携版时，解压并保持整个文件夹完整，双击 `OpenAC.exe`。当前开发分支同目录的九个工作进程需要保留，公开运行载荷白名单共19个文件；这不是已发布0.3包的文件数量。目标系统为 64 位 Windows 10/11 和 .NET Framework 4.8；本机 Windows 11 已验证。运行不需要开发工具。官网图片只用于本机预览；公开候选包仅保留图片来源清单，缺图时使用占位，本机已有官方安装资源可在运行时读取。

耳机、键鼠和主板灯控使用独立 USB 工作进程。LCD 和风扇控制器仍调用本机已安装的 ASUS SDK；这些 ASUS DLL 没有复制到发布包中，所以目前仍需要原安装环境。不会因启动新版而卸载原版、更新固件或自动应用设备设置。

此开发分支进入设备页时自动读取状态。每次重开程序或预览host，设备控制默认关闭；需要应用设置时，在“更新库”的“设备控制”区域勾选“启用设备控制”，随后手动应用；控制关闭时该区域默认展开。同一预览进程的热更新保留用户本次明确选择，仅存内存，不写磁盘、不从配置恢复许可、不自动Apply；新设备会话仍须重新读取。页面刷新不恢复宏播放。离线、未读回和本地草稿会分别标出；接口接受请求、设备读回相同和实体效果正常是不同结果，实体效果仍需实机验证。

用户已选择继续保留 MIT，独立补齐 G-Helper 功能，不复制其 GPL 应用实现。固定版本的逐项功能、已实现部分和缺口见 [GHelperFeatureParity.md](GHelperFeatureParity.md)。ASUS移动设备接口目前准备10个精确型号与6项手动SCI设置：性能模式、充电上限、键盘背光亮度、Overdrive、GPU Eco和MUX。每项仍需当前型号、已安装签名驱动、实际能力与当前会话校验；未有笔记本或掌机实机验证，多数写入仅能报告提交未确认，不提供曲线、功耗、电压或自动切换。见 [NotebookWorker-protocol.md](NotebookWorker-protocol.md)。官网 BIOS/驱动目录仅查询和提供下载链接，见 [Asus-Public-Catalog.md](Asus-Public-Catalog.md)。截图中七个项目的接口和许可研究见 [OpenSourceInterfaces.md](OpenSourceInterfaces.md)。

为保留前期本机预览的草稿，内部源码命名空间仍为 RogControl，本地游戏、宏、风扇名称和情境配置继续存于 `%LOCALAPPDATA%\ROG Control`。宏录制或播放需要用户显式启动；仅打开宏页面不会记录输入。停止、切换页面和关闭应用会取消播放，释放本应用按下的按键。

本轮灯控反馈已定位到两类界面问题：当前预览的设备控制开关关闭，而灯效/颜色仍可编辑本地草稿；重建后旧同步能力曾保留在卡片上。现在灰色应用与接管按钮会解释具体原因，旧会话能力和成功结果不再作为当前状态。尚未实写验证的接口显示“待验证”，动画收到完整首帧结果前显示等待，主板没有灯光读回时明确显示未确认。这些是状态与门禁修正；没有因此证明本机全部灯效已可用或原版神光同步故障已解决。同步勾选只是选择设备，仍需显式点击“应用同步”。

耳机另有仅PID7489的Aura静态请求通道：完整四项读取确认Aura已退出时，可显式启用LED、核对保留的旧recipe，再提交Static1及所选颜色/亮度并完整读回。原mode0不被冒充恒亮，启用与颜色提交不是原子事务；partial/拒绝/超时立即停止，不自动重试或恢复。软件动画已修复新通道后续帧曾被过滤为空的问题；现在每个相位都有真实请求计划，空计划不能计为成功帧。本机已只读确认最小通道返回完整字段与可提交能力，但没有耳机灯光实写验证。见 [GearLinkHeadsetLighting-protocol.md](GearLinkHeadsetLighting-protocol.md)。

## 新设备兼容

设备页点击“扫描已连接设备”，显示 Windows 当前确认的 ASUS USB/HID 硬件。未知型号只有身份资料，不创建控制适配、不加载插件、不下载驱动。接收器存在不代表无线键鼠在线；同型号多个物理 USB 父设备分别保留。拔插后重新扫描，已断开的新入口会从快照移除。没有自动监控热插拔。

本机已读到 62 个 ASUS 功能节点，合并为 9 个 USB 硬件，其中 ROG RYUO IV Standard、Airoha Headset Gaming 和 USB Audio 为新增仅识别入口；总线名称不证明完整型号或单独外设。详见 `Discovery-Implementation.md`。可控制功能仍取决于已有适配及实机验证，不承诺未来 ASUS 设备即插即控。

## 验证

模拟测试验证协议编码、参数边界、读写区分、崩溃/超时隔离、本地宏与游戏库规则，模拟通过不代表真实设备写入正常。

2026-10-14 开发分支的完整构建通过 53 组、17613 项纯检查，并通过热更新状态迁移验证。鼠标按键、灯光、校准和 Zone 已补充实际原版窗口对照；本轮没有修改真实设备设置或执行安装。

统一构建运行协议、监控、灯效协调、Windows电源和界面等纯检查，当前结果以 `build-all.ps1 -RunChecks` 输出为准。测试不调用真实设置接口。修正后的只读发现获得过 9 个 USB 硬件 / 62 个功能节点；响应不包含原始 USB 实例或设备容器标识。监控数据来源、单位及未知项目见 [Monitoring-Implementation.md](Monitoring-Implementation.md)。

已在本机只读获得 DELTA II-KJP 的8段均衡器、电源/侧音/降噪等状态，Windows播放和录音端点、Samsung 9100 PRO NVMe健康信息、LCD 720×1280尺寸及0109固件、控制器转速/温度和接收器配对状态。键鼠现已在线，验证细节见 [Hardware-Validation.md](https://github.com/Lucas0623z/OpenAC/blob/main/Hardware-Validation.md)。主板USB查询出现过15秒超时；改为原生有界读取后，主板查询/释放/再次查询、控制器和LCD的集成检查已通过。超时修复针对新版自身的设备工作进程，不表示已确定原版卡顿的根因。

耳机14项设置已用强制“同值不写”模式实机核对：全部返回当前值相同、`writeAttempted=false`；改变值的请求在实际写入前拒绝。这验证了读取和无操作保护，仍不代表真实修改已验证。

官方组件在线目录的未认证请求返回401，尚缺完整认证和安装校验流程。缓存中有比当前安装版本更旧的“服务器版本”，因此不能把缓存当作最新版本。

本轮仅对鼠标非当前第4档发送3200→3300→3200的可恢复测试；即时读回未确认修改，独立新读取已确认恢复400/800/1600/3200、当前档3及全部RGB。没有修改风扇、灯效、LCD内容、声音或固件，没有自动录制/播放宏，也没有启动游戏。实现证据及更细的接口限制见源码目录中的协议说明。

## 编译与测试

源码目录的 `build-all.ps1` 编译应用、九个运行工作进程及独立协议准备模块。九个为DirectAura、GearLink、SDK、Storage、AudioEndpoint、Discovery、Notebook、FanNative和WindowsBrightness。`-RunChecks` 执行模拟测试；`-HardwareReadOnlyChecks` 额外查询本机主板、风扇控制器和 LCD。后者需要相应设备及原安装SDK，不应在没有明确测试意图时运行。准备模块有独立协议门禁，不代表新增GUI完整硬件适配。外设只读回归工具为 `PeripheralReadOnlyTests.cs`。

设备工作进程各自隔离，出错或超时不应卡住界面。此项目没有绕过 ASUS 受信任进程校验，也不复用已经重复崩溃的旧键鼠SDK路径。

`package-candidate.ps1` 以精确白名单生成本地审核目录和 ZIP。默认 PublicCandidate 排除官网图、截图、原厂代码及本机报告；`-Mode LocalPreview` 额外保留本机预览用的六张官网原图。`-BuildAndCheck` 在打包前编译和运行纯检查。已有输出目录会拒绝覆盖，可用 `-OutputRoot` 指定项目内的新目录。用户已选择开源免费：自有代码采用标准MIT，源码和二进制均保留第三方署名，详见 LICENSE、THIRD-PARTY-NOTICES.md 与 PROVENANCE.md。公开预览源码包包含纯测试与安装器源码；源码仓库为 [Lucas0623z/OpenAC](https://github.com/Lucas0623z/OpenAC)，预览下载和状态以仓库 Releases 为准。

从源码构建安装包：先运行 `build-all.ps1 -RunChecks`，再运行 `package-candidate.ps1` 生成无图公开载荷，最后运行 `installer/build-installer.ps1 -PayloadDirectory <载荷目录> -RunChecks`。默认输出位于源码项目内；安装器只验证载荷，不实际安装。完整步骤见 [installer/README.md](https://github.com/Lucas0623z/OpenAC/blob/main/installer/README.md)。
